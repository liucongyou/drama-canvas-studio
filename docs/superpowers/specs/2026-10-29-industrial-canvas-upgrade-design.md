# 工业级自由画布与技能协同升级规格

日期：2026-10-29

状态：待产品审阅

## 1. 目标

把技能生成 JSON、导入编译器、自由画布、媒体资产和生成任务升级为同一套版本化产品。

升级后的系统必须达到以下结果：

- 同一集、同一份载荷重复导入得到稳定、可解释的语义结果。
- 旧项目、旧上传、旧媒体版本、旧任务和可信历史 JSON 不丢失。
- 技能与画布共用契约和错误码，不靠两边各自猜规则。
- 高风险数据问题、安全问题和已知回归不得进入主分支或生产环境。
- 大型画布仍能流畅浏览、选择、编辑和恢复。
- UI 操作、视觉反馈、错误恢复和键盘操作优于当前版本。
- 每次变更通过对应门禁后，按独立主题提交本地 Git。

“没有任何已知问题”是发布前必须满足的条件。“零未知问题”无法被工程承诺，因此以可量化回归门禁、灰度、观察和回滚代替口头保证。

## 2. 范围

本规格覆盖：

- 技能 JSON 契约与兼容输入。
- 导入预检、正式提交、幂等重导和跨集资产复用。
- 项目、节点、连线、布局、媒体版本和快照存储。
- 上传、媒体读取、缓存、对象存储转存。
- 生成队列、任务恢复、预算保护和供应商错误处理。
- 自由画布渲染、交互、键盘、视觉和可访问性。
- 多租户、账号、供应商配置和安全边界。
- 自动化测试、压测、浏览器验收、发布和回滚。

首个工业版本暂不承诺多人实时共同编辑同一节点。多标签页同步、冲突提示和乐观并发必须可靠；实时多人协作需要单独规格和 CRDT/服务端推送设计。

## 3. 审计基线

当前已确认的事实：

- 后端全量单元测试 162 项通过。
- 前端全量测试 216 项通过。
- Vite 正式构建通过。
- r10 技能 EP001、EP002、EP003 首次导入均通过双闸校验。
- 可信 WorkBuddy 载荷可通过；缺少 `voice_prompts` 的旧载荷会被拒绝。
- 同集重复导入不幂等。EP002 重导会改变 50 个语义字段并移除 4 个集节点 ID；EP003 会改变 35 个字段并移除 2 个集节点 ID。
- 同一集重导会把本集资产错误标记为复用或提示词过期。
- 占位资产可能替换已有角色的详细提示词。
- 供应商测试允许请求回环地址。实测 `127.0.0.1` 可被服务端访问并携带 Authorization。
- JSON API 没有请求体上限。
- 1000 节点实测首屏约 5.6 秒，DOM 约 48252 个，JS 堆约 141.8MB，最长阻塞任务约 1.27 秒。
- 1000 节点拖动帧间隔 p95 约 133ms，最大约 366ms。
- 1000 节点项目 60 个并发读取中位约 419ms，p95 约 570ms。
- 1000 节点下 24 个并发节点更新中位约 1.52 秒，最大约 1.81 秒。
- 独立 `tsc --noEmit` 失败，说明当前 Vite 构建不是完整类型门禁。
- 线上前端缺少 CSP、框架限制、Referrer Policy 和 Permissions Policy。

## 4. 核心原则

### 4.1 数据安全优先

任何会改写资产身份、引用、提示词、音色或生成上下文的操作，必须先经过纯预检，再在事务中提交。

### 4.2 兼容输入，错误关闭

- 旧字段可以读取和归一化。
- 旧字段归一化必须产生 warning。
- 缺少关键语义、身份冲突或引用无法确认时直接拒绝。
- 不通过静默补默认值制造看似成功的数据。

### 4.3 技能与画布共同版本化

技能包版本、契约版本、画布导入器版本和迁移器版本必须可追溯。

技能版本升级必须同时运行画布契约回归，不允许只测试技能自身。

### 4.4 不可见状态必须可解释

复用、占位、待生成、提示词过期、版本切换、任务等待和供应商失败必须在 UI 中有明确状态和下一步动作。

### 4.5 性能预算进入功能定义

新增功能如果没有定义内存、首屏、交互、存储和网络预算，不算完成。

### 4.6 不靠用户操作速度规避竞态

上传、自动保存、切集、重导、版本切换和任务完成必须通过请求协议解决竞态，不能依赖用户等待时间。

## 5. 产品边界

### 5.1 Skill Contract

职责：

- 定义技能允许输出的 JSON 版本和字段语义。
- 规范化图号、角色名、音色身份和引用格式。
- 生成 provenance。
- 在技能侧执行与画布共享的契约检查。

不负责：

- 画布节点 ID。
- 画布坐标。
- 运行时任务 ID。
- 浏览器本地状态。

### 5.2 Import Planner

职责：

- 运行时 Schema 校验。
- 调用共享语义规则。
- 从现有项目构建候选产物。
- 计算资产复用、占位、提示词变化、节点增删和 revision。
- 生成可供 UI 展示的语义 diff。
- 产出期望引用图，供提交后产物闸核对。

Planner 必须是无副作用纯函数，不写数据库、不写文件、不改 existing。

### 5.3 Import Committer

职责：

- 在 revision 和项目锁保护下提交候选产物。
- 保证同载荷幂等。
- 写入集级 provenance 和 warning。
- 失败时不修改项目。
- 支持同一计划的 dry-run 和正式提交共用。

### 5.4 Canvas Repository

职责：

- 项目、节点、连线、布局、备注、媒体版本和项目快照。
- 提供细粒度读写接口和事务。
- 对上层隐藏 SQLite 细节。
- 为未来 PostgreSQL、对象存储和独立 worker 保留适配边界。

首个工业版本继续使用每租户 SQLite，但必须开启 WAL、使用项目级锁，并提供 Repository 接口。

### 5.5 Generation Orchestrator

职责：

- 生成任务持久化。
- 租户和供应商并发控制。
- 重试、退避、取消、恢复和对账。
- 费用预估、预算上限和付费确认。
- 中文错误映射和可执行处理建议。

### 5.6 Canvas Runtime

职责：

- 视口、选择、拖拽、缩放、连线、分组、复制、撤销和恢复。
- 分级渲染和大图模式。
- 编辑弹窗、提示词引用、媒体播放和版本切换。
- 多标签页同步和冲突提示。
- 无障碍和键盘操作。

## 6. 导入与重导规格

### 6.1 图号规范化

- `图9`、`图09`、`图 9` 统一为同一 canonical code。
- 资产、音色、正文引用和连线比较全部使用 canonical code。
- 零填充冲突必须在 Gate 1 报 `ASSET_CODE_DUPLICATE` 或 `VOICE_CODE_CONFLICT`。

### 6.2 资产身份

角色资产身份至少包含：

- 资产类型。
- canonical 图号。
- 规范化角色或资产名称。
- `variantKey`。

音色身份至少包含：

- 角色名。
- canonical 图号。
- 音色格式版本。

### 6.3 占位优先级

- 已有详细提示词的节点不能被自动占位提示词覆盖。
- 如果技能新载荷明确表示提示词更新，保留旧素材并标记 `promptStale`。
- 如果只有占位信息，保留现有提示词并记录 missing 状态。
- 占位节点不能伪装成已复用已生成资产。

### 6.4 幂等定义

同一项目、同一集、同一 canonical feed 连续提交两次，除以下字段外，语义快照必须相同：

- `updatedAt`
- `importedAt`
- `lastImportedAt`
- provenance 中允许刷新且不改变语义的字段

必须保持：

- 节点 ID 集合。
- 视频和音频节点 ID。
- 集 `nodeIds` 集合。
- 连线端点集合。
- refs 和 voiceRefs 的目标集合。
- 资产 `assetKey`、`assetId`、`seriesId`、`variantKey`。
- 正式提示词正文。
- 占位和非占位状态。

### 6.5 重导差异分类

预检返回以下类别：

- 新增节点。
- 删除节点。
- 提示词更新。
- 素材版本过期。
- 资产复用。
- 新资产。
- 引用增删。
- 音色变化。
- 跨集身份冲突。
- 仅时间戳变化。

UI 默认折叠“仅时间戳变化”，但不得隐藏语义变化。

## 7. 契约与规则层

### 7.1 运行时 Schema

`schemas/canvas_feed.schema.json` 必须由运行时加载并作为结构闸执行。

结构 Schema 只负责：

- 类型。
- 必填字段。
- 枚举。
- 图号格式。
- 数组和对象结构。

跨数组、身份一致性和引用关系由共享语义模块负责。

### 7.2 单一规则源

技能校验器、画布 Gate 1 和 Gate 2 必须复用同一 Python 模块中的：

- 正则。
- canonical code。
- 台词解析。
- 音色引用解析。
- 资产引用解析。
- 错误码。

不允许 `gate_check.py` 再维护一套独立音色判断。

### 7.3 错误码

保留现有错误码，并补齐：

- `FEED_TOO_LARGE`
- `FEED_PATH_FORBIDDEN`
- `GENERATOR_METADATA_MISSING`
- `CODE_NOT_CANONICAL`
- `IDENTITY_CONFLICT`
- `SEGMENT_NO_DUPLICATE`
- `ASSET_PLACEHOLDER_WOULD_OVERWRITE`
- `IMPORT_NOT_IDEMPOTENT`

每个错误码必须有：

- 中文说明。
- JSON path。
- 段号或角色。
- 可执行修复建议。

## 8. 安全规格

### 8.1 SSRf 防护

所有服务端出站 URL 必须通过统一 URL 安全策略：

- 只允许 `http` 和 `https`。
- 拒绝回环、私网、链路本地、组播和保留地址。
- DNS 解析后的所有地址都必须通过检查。
- 重定向后重新检查目标地址。
- 禁止 file、ftp、gopher、data 等协议用于服务端请求。
- 供应商测试、实际生成、TOS 探针和任意连接测试共用同一策略。

### 8.2 请求边界

- 普通 JSON API 默认上限 8MB。
- 导入 JSON 单独上限 8MB。
- 上传继续使用分类上限。
- 超过上限返回 413，不读取完整请求体。
- 限制请求头和 JSON 嵌套深度。
- 对登录、导入、上传、生成和配置接口分别限速。

### 8.3 响应安全头

所有 HTML 和 API 响应至少包含：

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- 针对实际资源的 Content-Security-Policy
- HTTPS 环境下的 HSTS

### 8.4 本地路径

账号模式下禁止客户端指定服务器本地 `feed_path`。

只允许：

- 上传 JSON。
- 受控导入目录中的白名单文件。

### 8.5 审计日志

记录但不包含密钥：

- 登录成功和失败。
- 账号启停和密码重置。
- 供应商和模型配置变更。
- TOS 配置变更。
- 导入预检和提交。
- 付费生成提交。
- 配置测试。

## 9. 存储与并发规格

### 9.1 SQLite

每个租户数据库开启：

- WAL。
- `busy_timeout`。
- 短事务。
- 项目级锁，不使用跨租户全局项目写锁。

### 9.2 Repository

至少提供：

- `get_project`
- `list_projects`
- `create_project`
- `patch_project_metadata`
- `upsert_nodes`
- `patch_node`
- `delete_nodes`
- `patch_edges`
- `save_viewport`
- `create_snapshot`
- `restore_snapshot`

每条写接口必须声明 revision 前置条件和返回新 revision。

### 9.3 快照

- 自动快照按时间或逻辑操作节流，不能每次输入字符都生成整包快照。
- 用户手动创建的项目版本不参与自动裁剪。
- 自动恢复快照保留配置化数量和时间窗口。
- 支持项目版本预览和恢复。

### 9.4 未来扩容

上层不能直接依赖 SQLite 连接。

首个版本保持单实例控制面，但 Repository 和 Orchestrator 接口不得阻止未来接入 PostgreSQL、Redis 队列和独立 worker。

## 10. 画布性能规格

### 10.1 分级渲染

- 远视图只显示卡片骨架、缩略图、标题和状态。
- 中视图显示基础操作。
- 近视图显示完整控件。
- 视口外节点不挂载昂贵播放器、完整菜单和大图。

### 10.2 媒体

- 图片使用尺寸受控缩略图和延迟加载。
- 视频只在可见且用户操作后激活播放器。
- 音频仅在可见时计算真实波形。
- 版本切换只替换媒体，不重建整张画布。

### 10.3 交互

- 拖动期间只更新必要的 React Flow 状态。
- 工具条、端口、缩略图和弹层不因媒体加载改变布局。
- 选择、多选、框选、复制、剪切和撤销都经过固定回归。

### 10.4 性能预算

在 1000 节点、混合图片和视频占位卡、桌面 1440×1000 环境下：

- 首屏可交互目标小于 3 秒。
- DOM 节点目标小于 20000。
- JS 堆目标小于 100MB。
- 单次主线程长任务目标小于 200ms。
- 拖动帧间隔 p95 目标小于 33ms。
- 移动端无横向溢出。

性能预算不达标时不得宣称大画布模式完成。

## 11. 用户体验规格

### 11.1 导入体验

- 导入前展示集数、节点、资产、引用和 warning 摘要。
- 正式提交前显示语义 diff。
- 导入完成后明确区分“结构导入成功”和“生产就绪”。
- 失败结果定位到集、段、角色和图号。

### 11.2 画布体验

- 空白项目可直接操作。
- 新建节点、上传、生成和导入入口一致。
- 单击、双击、右键、拖动和弹窗行为稳定。
- Esc、Delete、Ctrl+D、Ctrl+X、Ctrl+V、Ctrl+Z 和 Shift+Z 行为明确。
- 键盘焦点不自动抢入输入框。
- 对话框具备焦点陷阱、关闭恢复和屏幕阅读器标签。

### 11.3 错误体验

错误分为：

- 输入可修复。
- 本地数据缺失。
- 权限或会话问题。
- 供应商可重试。
- 供应商不可重试。
- 计费风险。

每类错误必须给出下一步操作。

### 11.4 视觉

- 所有核心表面使用统一主题令牌。
- 画布、弹窗、任务中心和媒体卡的状态颜色一致。
- 大画布远视图仍能辨认集、段和资产类别。
- 不使用遮挡画布主操作的装饰性布局。

## 12. 生成与成本规格

- 生成按钮只在用户明确点击后提交。
- 提交前展示模型、比例、分辨率、时长、引用数量和费用预估。
- 超额、缺引用、参数越界和缺密钥在本地阻断。
- 任务中心区分本地引用错误和供应商失败。
- 费用未知时显示“按供应商账单”，不显示猜测金额。
- 同一模型不同分辨率、时长和参考视频必须使用对应计费规则。

## 14. 发布与 Git 规则

每次逻辑变更完成后单独提交本地 Git。

提交主题：

- `contract:`
- `import:`
- `security:`
- `data:`
- `perf:`
- `ux:`
- `test:`
- `docs:`

禁止：

- 测试失败仍提交“已完成”。
- 把不相关的重构混入修复提交。
- 未经确认删除旧项目或旧素材。
- 用生产项目验证会写数据的导入。
- 自动触发真实付费生成。

每次发布前：

- 通过对应门禁。
- 生成变更清单。
- 创建部署前备份。
- 记录前端资源哈希和后端文件哈希。
- 部署后验证服务、API、登录页、资源加载和关键浏览器流程。
- 保留回滚包。

## 15. 兼容与迁移

- 不要求用户重新生成现有集。
- 旧项目通过幂等迁移器升级。
- 迁移前创建数据库备份。
- 迁移必须可重复执行。
- 迁移失败不得修改原项目。
- 媒体版本和任务历史保留。
- 技能旧字段归一化产生 warning。
- 无法确认身份的旧资产进入人工确认清单，不静默合并。

## 16. 验收标准

### P0

- 同载荷重导完全幂等。
- 占位资产不覆盖已有提示词。
- 资产、音色、引用和连线集合稳定。
- SSRF、请求体上限、安全头和本地路径问题修复。
- 所有新增 P0 负例先红后绿。

### P1

- 运行时 Schema 生效。
- 技能和画布共享一张规则表。
- 仓储增量和项目级锁生效。
- 1000 节点性能达到预算。
- 项目版本恢复、任务中心、错误映射和费用保护完成。
- TypeScript 严格门禁通过。

### P2

- 大画布分级渲染和移动端体验完成。
- 多标签冲突和恢复体验完成。
- 无障碍、视觉令牌、监控、审计、配额和容量治理完成。
- 性能、浏览器、安全、兼容矩阵全部进入持续回归。

## 17. 非目标

首个工业版本不包含：

- 多人实时共同编辑同一节点的 CRDT。
- 任意脚本执行。
- 浏览器直接保存供应商密钥。
- 自动付费批量生成。
- 在未获得用户确认时自动补生成资产。
- 将技能 JSON 作为画布内部数据库格式直接落库。

## 18. 交付方式

规格批准后先编写实施计划。

实施按三个里程碑推进：

1. P0 数据与安全闭环。
2. P1 导入、存储、任务和性能底座。
3. P2 画布体验、可访问性、监控和规模化。

每个里程碑完成后：

- 更新测试矩阵。
- 运行全量回归。
- 浏览器和压测复验。
- 单独提交本地 Git。
- 汇报实际指标和剩余风险。
