# 06 · 开发实施计划

## 1. 总体节奏

按“先验证契约，再做闭环，最后做平台化”的顺序。假设 1 名后端 + 1 名前端 + 0.5 名测试：

| 阶段 | 周期 | 目标 |
|---|---|---|
| Phase 0 · 契约验证 | 1 周 | 证明“现有技能 → feed → 现有导入”能跑通，选好模型 |
| Phase 1 · MVP 闭环 | 3–4 周 | 技能上传、Agent 对话、feed 预检、预览导入、侧栏 |
| Phase 2 · 生产可用 | 3–4 周 | 上下文检索、修复循环、恢复/预算/历史/评测 |
| Phase 3 · 平台化 | 按需 | 脚本沙箱、配额、协作、技能市场/分享 |

**不建议跳 Phase 0 直接做 UI。**

---

## 2. Phase 0：契约验证（1 周）

### 交付物

1. 用现有 V7.4.29 技能包手工跑一次：
   - `build_board_lite.py` 产出 feed；
   - `prepare_import` 预检通过；
   - 导入一个测试项目，节点/连线/音色/资产复用正确。
2. 用 1 个文本模型跑“读技能入口 → 产出 feed”的最小闭环（可人工修正）。
3. 选定 Agent 对话模型（支持 tool calling 优先），记录 token 成本。
4. 产出《契约验证报告》，列出模型/技能/导入的坑。

### 验收

- [ ] 一次完整导入，revision/集/资产/音色均正确。
- [ ] 失败 feed 能被 `prepare_import` 拦截，原项目不变。
- [ ] 明确 MVP 的模型/上下文上限/平均 token 成本。
- [ ] 决定“脚本 exporter 是否进 MVP”。

## 3. Phase 1：MVP 闭环（3–4 周）

### 范围

- 技能上传/校验/激活（单包，先不做市场）。
- Agent 运行（prompt 模式，单一技能套件）。
- 项目只读上下文（brief + 资产台账）。
- 锁题卡（至少支持 6 锁 + 画风）。
- 产物：feed JSON + brief。
- 服务端预检 + 结构化错误展示 + 最多 1 轮自动修复（Phase 2 扩到 2 轮）。
- 导入预览 + 确认 + 现有导入 + 画布刷新。

### MVP 验收

- [ ] 上传现有 V7.4.29 套件，校验报告正确；hash 不一致会被拒。
- [ ] 从一句话开始，Agent 能问完锁题并产出 feed。
- [ ] feed 预检错误可定位到 segment/role/code。
- [ ] 至少 1 轮自动修复可把常见错误修到通过。
- [ ] 预览显示新增/复用节点/连线，确认后导入成功。
- [ ] 导入失败（schema/接线/revision）不写库，画布不变。
- [ ] 只读分享不能运行/导入。
- [ ] 关闭面板/刷新页面，运行可恢复或安全失败。
- [ ] 手动导入路径完全不受影响（回归测试）。

## 4. Phase 2：生产可用（3–4 周）

- 技能上下文检索/切片（stage documents + search/read），控制 token。
- 自动修复循环（最多 2 轮）+ 修复前后 diff。
- 运行恢复/断点续跑/completed run 复制。
- token/费用预算、超限暂停/拒绝、用量页。
- 多技能套件/子技能选择；技能版本对比。
- 评测集：10–20 个真实题材，结构断言 + 导入成功率。
- 运行指标/告警/审计查询。
- 体验：历史、继续、产物 diff、错误文案。

### 验收指标

- 首次预检通过率 ≥ 60%（MVP 可低，Phase 2 目标）。
- 修复后导入成功率 ≥ 90%。
- 平均运行 token 成本可解释；超预算 0 静默。
- 运行中断恢复成功率 ≥ 95%。
- 手动导入回归 100% 通过。

---

## 5. Phase 3：平台化（按需）

- 脚本 exporter 沙箱（容器/子进程、无网络、限额）。
- 技能签名/可信发布；租户间导出/导入。
- 多用户协作：共享 run、评论、审批。
- 技能市场（可选）。
- 成本分摊/配额/账单。
- A/B 评测、自动回归。

## 6. 测试矩阵

| 层级 | 内容 | 工具 |
|---|---|---|
| 契约 | schema/hash、合法/非法 feed、两闸、revision | pytest + 现有 `test_canvas_feed_*` |
| 技能包 | zip 安全、manifest、legacy adapter、hash 不一致 | pytest |
| Runtime | 状态机、工具、锁题、修复、取消/恢复、预算 | pytest + mock LLM |
| API | 鉴权、租户、CRUD、SSE、错误码 | pytest HTTP |
| 前端 | 面板、锁题、SSE、预览、导入、空错 | Vitest + Testing Library |
| E2E | 上传→运行→锁题→feed→预览→导入→画布刷新 | Playwright |
| 回归 | 现有手动导入、画布编辑、生成、分享 | 现有测试 + smoke |
| 安全 | 路径穿越/zip slip/符号链接/XSS/越权/注入 | pytest + 手工 |
| 性能 | 50 并发 run、SSE 100 连接、约 191 文件上传 | locust/k6 或脚本 |

**E2E 关键用例：**

1. 上传 V7.4.29 → 激活 → 创建 run → 回答锁题 → 产出 feed → 预览 → 导入 → 画布出现新集/资产/连线。
2. 预检错误 → 修复一轮 → 通过 → 导入。
3. revision 冲突 → 预览重检 → 用户确认。
4. 取消 run → 无残留、无导入。
5. 只读分享 → 无入口/403。
6. 手动导入旧 feed → 行为与改动前一致。

## 7. 发布与回滚

- 功能开关：`agent.enabled`（租户级/全局），默认关闭。
- 灰度：内部项目 → 1 个租户 → 全量。
- 技能库与 run 数据独立表；关闭开关不影响画布。
- 导入仍走现有接口；回滚只需关闭 Agent 入口，已导入数据不受影响。
- 数据库迁移只加表/索引；不修改现有表结构（除可选 provenance 字段）。
- 备份：上线前备份 DB；技能/产物目录单独备份。
- 监控：run 失败率、导入失败率、SSE 断线、token 成本；异常自动关闭开关（人工）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型输出不稳定 | feed 结构错 | 确定性 exporter + 两闸 + 修复循环 + 评测 |
| 技能包过大 | 上下文爆炸/慢 | manifest 分阶段 + 检索 + 产物接力 |
| 用户上传恶意代码 | RCE | 默认不执行；沙箱/白名单/签名 |
| 自动导入误写 | 数据损坏 | 永不自动；预览 + revision + 快照 |
| 重复建资产 | 画布膨胀 | 资产台账 + series/variant 复用 + 预检 |
| 长 run 成本 | 费用不可控 | 预算/超时/取消/用量 |
| 多租户越权 | 数据泄露 | tenant scope + 路径校验 + 权限测试 |
| 模型/供应商不可用 | 功能不可用 | 降级手动导入；重试；错误提示 |
| 维护两套契约 | 长期漂移 | 只保留 v2；hash 同步；v3 才分支 |

## 9. Definition of Done（MVP）

- [ ] 文档、Schema、manifest、API、DB 迁移齐全。
- [ ] 技能上传/激活/回滚可用，校验失败不可激活。
- [ ] Agent 能完成至少 1 个真实项目的端到端 feed。
- [ ] 预检/预览/导入/刷新全链路通过。
- [ ] 失败/取消/超时/冲突都有明确状态与文案。
- [ ] 现有画布与手动导入回归通过。
- [ ] 审计、日志、指标可查。
- [ ] 只读/越权测试通过。
- [ ] 用户可在 3 分钟内完成第一次“技能→导入”。
