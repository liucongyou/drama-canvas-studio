# 第 26 轮：拖动辅助线改成即梦那套（2026-11-02）

用户两次贴截图反馈「很难跟上面对齐」，并给了即梦的对照图（两张能量卡并排时，
上/中/下三条虚线同时出现，每条只连两卡之间的空隙，没有数字）。

## 一、先测，再改

在隔离实例（复制一份 `canvas.db`，独立端口 8892，host 模式免登录，不碰真实数据）上
用 puppeteer 以 59% 缩放做慢速拖动，逐帧读 `getBoundingClientRect` 与 DOM 样式：

| 观测 | 结果 |
|---|---|
| 参考线落点 vs 目标卡左边框 | 吸附后完全重合（670.1 vs 670.1），**坐标换算没毛病** |
| 拖动跟手比 | 指针移 8 屏幕 px，卡片移 8 屏幕 px（1:1，正常） |
| 指针在 26px 内移动 | 卡片**完全不动**（glue 死区），超过后才猛跳 —— 手感"卡住"的来源 |
| 线长 | 取「被拖 ∪ 目标」并集再外扩 24px，常横穿半个画布 |
| 同轴线条数 | 永远 1 条，即使上/中/下三条边都对齐 |
| 读数 | 两轴各一块小蓝牌，会在卡片左上角叠住，且每帧跳动 |

结论：不是坐标 bug，是**呈现模型**和**吸附档位**的问题。

## 二、改了什么

### canvasLayout.ts

- 新增 `alignGuideSegments(moving, others, eps)`：把**所有**已对齐的锚点对都收集起来，
  按垂直于线的空隙排序（近的优先，最多 4 条/轴）。
- 新增 `segmentOf()`：线只画两个盒子之间那一段。不重叠 → 中间空隙；
  重叠 → 重叠区；重叠区太短（<12px）才用并集兜底。
- `solveAlignSnap` / `computeAlignSnap` 的 `guides` 改为上述分段，不再带 `delta`。
- 档位 `ALIGN_ENTER/GLUE/RELEASE` 从 6/26/44 收到 **8/14/22**（屏幕 px）：
  吸住区更短、滑出带更窄，指针不会出现"推不动"的错觉。
- 新增 `finiteBox()` 守卫：`measured` 还没出来的节点会给出 `x + undefined = NaN`，
  而 NaN 的所有比较都是 false，会穿过全部阈值守卫变成"最佳候选"，
  把线的位置和吸附量一起污染成 NaN（样式写 `NaNpx` 被浏览器丢弃 → 线停在上一帧、卡片僵住）。

### CanvasView.tsx

- `updateAlignGuides` 改为**节点池**：`<div class="canvas-align-guides">` 里按需
  创建最多 8 个 div 复用，一次画多条；带 NaN 守卫和"容器被重建则重置池"的保护。
- 删除读数标签的全部逻辑（`.canvas-align-guide-label` 的 DOM/refs/样式）。
- 删除 `liveGuides`（"即将对齐"的预览线）—— 现在只有真对齐才画线，和即梦一致。
- `dx/dy` 加 `Number.isFinite` 兜底，非有限值按 0 处理。

### styles.css

- 参考线改**虚线**：`repeating-linear-gradient` + `--dash`（JS 按 `1/zoom` 写入，
  屏幕恒为 4px 实 4px 空），线宽仍是 `1/zoom`（屏幕 1px）。
- 颜色仍取 `--v-accent`，去掉 `box-shadow` 光晕（不再和连线高亮抢注意力）。
