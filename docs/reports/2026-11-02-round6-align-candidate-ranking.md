# 对齐辅助线：候选目标排序修复（第六轮）

## 用户反馈

> 「你看类似这样的很难跟上面对齐」（附截图，红框圈出「下方卡片左边缘对不上正上方卡片」，
> 画面里辅助线已画出、标签显示 `+3` / `+10`，但没有吸住）

## 复现与定位

放大截图后可确认：紫色竖线在、读数在，但线指向的目标与"想对齐的那张卡"不是同一个。
用真实画布尺寸（`canvas.db`：图片卡 720×405、视频卡 420×746.7）跑纯函数，稳定复现：

被拖的视频卡左边缘距**正上方**图片卡 3px（垂直空隙 95），距**同排邻居** 20px（空隙 0）。

| | 旧实现 `hypot(|delta|, 空隙)` | 修复后 `先齐再近` |
|---|---|---|
| 画出的竖线 | pos=443（同排邻居），delta **+20** | pos=0（正上方），delta **-3** |
| 吸附目标 | 正上方（阈值内只剩它） | 正上方 |
| 是否同源 | ❌ 线与吸附各选各的 | ✅ 同一个目标 |

根因在 `canvasLayout.ts` 的 `findBestCandidate`：它把「垂直于参考线方向的空隙」直接算进
打分 `Math.hypot(absDelta, lateralGap)`，于是

- 3px 对齐 + 95px 空隙 → 95.1 分
- 20px 对齐 + 0 空隙 → 20 分

**"离得近"系统性压过"对得齐"**。画布是按列排的卡片，任何跨列对齐（想让下面那张卡对上正上
方那张）都会被同排邻居抢先吸走，表现就是"越往上挪越被旁边的卡拽回去"。同时因为画线用的是
`visible` 阈值、吸附用的是 `enter` 阈值，两者候选集不同 → 线指向 A、实际吸到 B，视觉上就是
"线在那儿但不吸"。

## 改动

`web-vimax/src/canvasLayout.ts` · `findBestCandidate`

```ts
const ALIGN_DELTA_EPS = 0.75;   // 画布 px

// 偏差明显更小 → 直接换（哪怕离得远）
absDelta < bestAbs - ALIGN_DELTA_EPS
// 精度打平 → 才用空间距离挑更近的，避免拉一条横跨半个画布的长线
|| (Math.abs(absDelta - bestAbs) <= ALIGN_DELTA_EPS && lateralGap < best.lateralGap)
```

阈值（`ALIGN_ENTER_PX` = 8 / `ALIGN_VISIBLE_PX` = 20，屏幕 px）**不动**：靠近才吸、远处只预览
的语义是对的，问题只在"预览的那条线"和"最终吸的那条线"不是同一条。

## 顺带提示用户的另一种"对不齐"

多选（2 张及以上）状态下拖动时，参与对齐的是**整组的包围盒**，不是单张卡的边缘
（Figma 同款行为）。想让某一张卡的左边贴住上面那张，要单选那张卡再拖。
