# 第 5 轮：拖动辅助线打磨 + 本机模式 403

版本 `2026.11.02.06` · 2026-11-02

用户反馈「拖动辅助线可以再打磨优化下」。这次没有凭感觉改，先用 puppeteer 在
真实画布上慢速拖动，逐帧采样 `.canvas-align-guide*` 的 computed style 和
`getBoundingClientRect()`，把"哪里别扭"变成可量化的三条。

---

## 一、辅助线读数：三个硬伤

实测环境：项目 `gk6woLnGjh998UeNwvhqYG`（127 节点），视口 1680×1050，缩放 50%。

### 1. 刻度不是用户看到的刻度

慢拖过程中采到的读数序列：

```
+74.7 → +81.2 → +36 → +34 → +30 → ... → +16 → 0
```

`ALIGN_RELEASE_PX = 44`（屏幕像素），但读数出现 **+81.2**。原因：`delta` 是
**画布坐标**，50% 缩放下画布 88px 只有屏幕上 44px。标签直接把画布值印出来，
缩放越小，数字越夸张，用户对着屏幕量半天也量不出那个数。

→ 新增纯函数 `alignGuideReadout(delta, zoom)`：`|delta × zoom|` 取整成屏幕像素。

### 2. 对齐成功后仍挂一个 "0"

吸附锁住之后 `delta` 恒为 0，横竖两条标签各印一个 "0" 浮在卡片上，
一次拖动里从头到尾都在。标签本意是"还差多少"，差 0 的时候它只是噪音。

→ 不足 0.5 屏幕像素视为已对齐，返回空串，调用方隐藏标签。
"已经对齐"由线本身 + 卡片被磁住表达，不再写个 0。

### 3. 标签贴在线段顶端，离视线很远

原实现 `top = lo`（线段起点）。而线段区间是「被拖动组 + 对齐目标」的并集
再各外扩 24 屏幕像素，起点往往已经在卡片上方几十像素的空白里；卡片矮的时候
起点甚至不在同一屏。

→ 改为贴着**被拖卡片**定位（新增第三个参数 `moving`）：
- 竖线读数浮在卡片上边缘之外、水平居中于参考线（`.is-above`）
- 横线读数贴在卡片左边缘之外、垂直居中于参考线（`.is-left`）

实测改后 70 帧拖动里，标签与任何卡片的矩形交叠次数 **0**。

## 二、线身：渐变把线"洗断"了

```
background: linear-gradient(180deg, #5d62e9 0%, #9ccdff 50%, #5d62e9 100%)
```

`#9ccdff` 在浅色画布（#f4f7fd 一带）上几乎是白色，1px 线走到中段就淡没了——
肉眼是一条**中间断掉的虚线**。截图里能直接看到。

同时这条线混了三种蓝：硬编码靛蓝 `#5d62e9`（线）+ `#9ccdff`（渐变芯）
+ `rgba(77,159,255,.42)`（光晕）。而浅色主题的 `--v-accent` 其实是 `#2f6feb`。

→ 改成纯色实线，颜色全量接令牌：

| | 改前 | 改后 |
|---|---|---|
| 线色 | `linear-gradient(#5d62e9 → #9ccdff)` | `var(--v-accent)` |
| 光晕 | `rgba(77,159,255,.42)` 硬编码 | `var(--v-accent-glow)` |
| 浅色主题实际渲染 | `rgb(93,98,233)`（暗色主题的蓝） | `rgb(47,111,235)`（正确） |

线要的是"准"不是"亮"，1px 纯色反而更利落（Figma / 即梦同款）。

## 三、顺带修掉的真 BUG：本机模式每 30 秒一条 403

浏览器跑 20 秒，控制台稳定出现：

```
403 GET /api/admin/accounts   (×2)
```

链路：`Shell` 有个 30 秒轮询，只为拿 `onlineCount`；服务端
`_handle_admin_list_accounts` 先走 `_admin_session()`，而本机单用户模式
（`CANVAS_AUTH_MODE != accounts`）根本没有账号表 → 直接 403 `ADMIN_REQUIRED`。

后果：
- 控制台每 30 秒一条红字，**"0 报错"永远做不到**；
- 「账号管理」弹窗在本机模式下必然报错；
- 「修改密码」点了回 401「请先登录」（改密要 `account_id`，本机没有）。

修法：
1. `server.py`：本机模式按事实返回 `{accounts: [], onlineCount: 1, local: true}`，
   不再 403；accounts 模式仍然要求管理员（未登录 401 / 非管理员 403）。
2. `main.tsx`：`localMode` 时**一次都不发**这个请求，`onlineCount` 初始值直接给 1
   （否则顶栏会永久停在「在线状态同步中」）。
3. 本机模式隐藏「修改密码」「创建账号」两个入口。

## 五、本轮审计发现但**没有动**的（等你决定）

1. **空闲轮询**：SSE 已连通且没有任何任务在跑时，画布仍每 7 秒拉一次
   `workspace-nodes`；`AuthGate` 每 60 秒拉一次 `/api/auth/session` 且**丢弃返回值**
   （只是心跳）。15 秒静置共 12 个请求。收益不大但都是白流量。
2. **`data/` 下 48 个 `canvas.db.bak-*` 共 8.8GB**（当前库仅 30MB、freelist 0）。
3. **根目录 497 个 `_tmp_*`**。
4. **CSS 583KB**：去重/拆分要动"只能就地改原声明"的约定，需单独排期。
5. `express` 之外无 `keep-alive`：评估过，`ThreadingHTTPServer` 每空闲连接常驻线程，
   收益 < 代价，维持现状。

> 提醒：`server.py` 的改动**必须重启后端进程**才生效（8890 目前跑的还是旧代码）。
