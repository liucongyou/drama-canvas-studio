# 前端媒体加载体验审计与修复

日期：2026-11-13

## 审计结论

前端原有媒体状态把“后端任务完成”和“浏览器已能展示素材”混成一个状态，导致刷新、历史版本切换和视频首帧加载时提前显示“已生成”。同时，媒体加载失败状态虽被记录但没有展示，视频控件也可能在元数据就绪前出现。

## 已修复

- 新增 `mediaReadiness.ts` 统一状态机：`生成中`、`素材加载中`、`已生成`、`素材加载失败`、`生成失败`、`媒体文件丢失`。
- 图片以 `img onLoad` 为就绪依据。
- 视频以封面图片真正加载完成、真实视频帧就绪，或视频元数据成功但封面提取不可用时为就绪依据。
- 音频以 `loadedmetadata` 为就绪依据。
- 刷新页面或切换历史版本后，先显示“素材加载中”，不会提前显示“已生成”。
- 视频播放按钮和进度控件在视频元数据/帧就绪前隐藏，避免刷新后过早点击造成黑屏或播放失败。
- 媒体重试耗尽后显示“素材加载失败 · 重试”，点击状态栏可重新加载。
- 后端明确返回 `mediaAvailability=missing` 时仍以“媒体文件丢失”为准，不用浏览器加载结果猜测文件是否存在。
- 任务中心“确认失败”由浏览器原生确认框改为站内通知对话框，保持交互一致。

## 验证

- 新增 `mediaReadiness.test.ts`。
- 更新 `mediaCardStatus.test.ts`，覆盖“后端完成但素材未就绪”和“素材加载失败可重试”。
- 更新 `videoCoverLoading.test.ts`，覆盖视频封面回调、播放控件延迟和失败重试入口。
- 前端完整测试：79 个测试文件，741/742 项通过；并行回归中一个历史 SQLite 分页用例因负载超时，单独复跑 439ms 通过。
- 前端 Canvas 类型检查：通过。
- 前端生产构建：通过，入口为 `index-oNU3O9MS.js`。

本次只修改前端展示和就绪状态，不改供应商接口，不触发任何图片、音频或视频生成。
