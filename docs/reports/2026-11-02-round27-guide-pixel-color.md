# 第 27 轮：参考线「有深有浅」与「少一根」

日期：2026-11-02
版本：`2026.11.02.08`
涉及文件：`web-vimax/src/canvasLayout.ts`、`web-vimax/src/CanvasView.tsx`、`web-vimax/src/canvasLayout.test.ts`

## 一、用户反馈

1. 「为什么虚线颜色有深有浅，都要深色的」（附截图，红框内三条竖虚线深浅明显不同）
2. 「怎么对齐上面的节点卡片会少一根虚线？」
3. 「你刚才没改颜色之前好好的」

## 二、深浅不一的根因（量化）

对截图（901×578）做逐像素统计，把所有偏蓝像素按行列聚类：

| 线 | 落点 | 峰值像素 | 说明 |
|---|---|---|---|
| 竖线 1 | x=593 | (11,111,171) | 单列纯色，最深 |
| 竖线 2 | x=637 | (11,65,96) | **整列只有一档浅色** |
| 竖线 3 | x=680 + 681 | (24,68,94) / (9,72,109) | **被劈成两列** |
| 横线 1 | y=379 | (8,70,107) | 单行 |
| 横线 2 | y=422 + 423 | (7,80,123) / (11,66,98) | 劈成两行 |

色相完全一致，只是一串**亮度梯度**。这是 1 物理像素宽的矩形压在非整数像素边界上的典型结果：
浏览器把它拆给相邻两列，每列各拿 ~50% 覆盖，颜色被背景冲淡一半。

线宽 `thickness = 1/zoom` 是连续值，`left/top` 又是浮点画布坐标，
`world * zoom + pan` 落在 `x.5` 时必然被劈开。落在整数边界的深、落在半像素的浅。

## 三、少一根的根因

`alignGuideSegments` 旧实现：每命中一个「锚点对」就 push 一条线，只按
`axis:pos:from:to` 去重。

用户项目 `gk6woLnGjh998UeNwvhqYG` 的真实几何：

- `x=0` 上有 **5 张**图片卡（y=0/360/720/1080/1080）
- `x=640` 上有 **3 张**
- `x=1240` 上有 **4 张**

拖一张卡到这些列上时，同一条边同时命中 4~5 张卡 → 生成 4~5 条**完全重合**的线：

1. 它们互相覆盖，屏幕上只看到一根（还因为抗锯齿边缘叠加而更"深"）；
2. 每轴只有 4 个名额（`count >= 4`），名额被同一位置的重复线吃光，
   于是**真正不同的边（中线、右边缘）一条都画不出来** → 用户看到"少一根"。

## 四、踩的坑（已回退）

中途曾把虚线图案锚到画布坐标做「相位统一」（让所有平行线的实/空段对齐）。
结果：虚线周期 8px（4 实 + 4 空），两卡之间那段窄缝的起点正好落进"空"档，
**整根短线只剩一两段、或完全看不见** —— 正好加重了"少一根"。

已回退：每条线都从自己的起点画实段（`backgroundPosition: 0 0`），短线一定有内容。

## 五、改法

### 1. 像素对齐（`canvasLayout.snapToPixel`）

```ts
export function snapToPixel(world: number, zoom: number, pan: number): number {
  if (!Number.isFinite(world) || !Number.isFinite(pan)) return world;
  if (!Number.isFinite(zoom) || zoom === 0) return world;
  return (Math.round(world * zoom + pan) - pan) / zoom;
}
```

线的屏幕坐标四舍五入到整数 CSS 像素，再反算回画布坐标。偏差 ≤0.5 屏幕像素，
肉眼无感；但线恒为「整一格纯色」，任何缩放都一致。

### 2. 同一条边只画一根（`alignGuideSegments`）

按 `Math.round(pos * 2) / 2`（0.5 画布像素）聚合，区间取并集，名额留给真正不同的边。
聚合后仍按「垂直于线的空隙」排序，超过 4 条时挤掉远处的。

### 3. 渲染层兜底合并（`updateAlignGuides`）

像素对齐后，两条原本只差零点几像素的线会进同一屏幕列，后画的会把先画的整根盖住。
渲染前再按「轴 + 吸附后位置」合并一次区间，保证一列只画一根、且覆盖全部命中区间。
